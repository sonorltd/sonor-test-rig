Bench Pi 5 build guide

One Raspberry Pi 5 that hosts every Sonor studio project side by side — Pixel Conductor, the Fractal Rig, the C-Bus daemon and the eDIN+ bridge — with a 7" touch panel and an HDMI output pointed at whichever one is being worked on. This page is the complete set of instructions for building it from a blank SD card. Allow about an hour, most of it waiting for installs.

hostname sonorpi
all four daemons running at once
Ethernet → studio switch
Projector / TVHDMI-A-2
Fractal Rig renderer, fullscreen, when Fractal is the front app

Each project is installed exactly as it would be on its own dedicated Pi (the rig runs each project's own installer). A thin layer called sonor-rig sits on top: it clones and installs the projects, keeps their services running, and switches which one owns the touch panel and the second screen. Switching is one command — sonor-rig use fractal — and nothing else stops.

Field Pis on customer sites stay one app per Pi and never see this repo. The rig is a bench tool.

Optional hardware (leave the simulators on without it)

  • Gledopto / WLED pixel nodes on the same LAN (Pixel Conductor). Without them set ARGS=--simulate in /etc/sonor-rig/pixel.env.
  • C-Bus: a 5500PC via FTDI USB-serial (/dev/ttyUSB0) or a 5500CN2 on the LAN. Without one the daemon runs its simulator.
  • USB audio interface (Fractal master --audio, Pixel Conductor audio input); Pioneer DJ gear on the LAN for Pro DJ Link beat sync.

Cabling

  1. Touch panel → HDMI-A-1. That is the micro-HDMI socket next to the USB-C power socket. Also plug the panel's USB lead into any USB port (touch input).
  2. Projector / TV → HDMI-A-2 (the other micro-HDMI).
  3. Ethernet to the studio switch.
  4. Any FTDI / USB-serial or USB audio you have to hand.
  5. Power last, once the card is in.
Which HDMI is which matters: the kiosk lands on the first output and the Fractal renderer goes to the second. If they come up swapped it is a one-line fix (Two screens), but getting the cables right first saves the head-scratching.

1 Image the SD card

Open Raspberry Pi Imager on the Mac/PC.

  • Device: Raspberry Pi 5.
  • OS: Raspberry Pi OS (64-bit) — the one with desktop, Bookworm or later. Not "Lite": the Fractal renderer and a Chromium kiosk cannot share the GPU on Lite (KMSDRM allows one owner); under the desktop compositor both are ordinary windows on two outputs.
  • When asked "Would you like to apply OS customisation settings?" → Edit settings:
    • Hostname: sonorpi
    • Username: pi, choose a password (write it on the handover sheet)
    • Wi-Fi: only if there is no Ethernet; set country GB
    • Locale: timezone Europe/London, keyboard gb
    • Services tab: Enable SSH, password authentication
  • Write, then put the card in the Pi and power up. First boot takes a minute or two; the desktop appears on the panel.

2 First boot — update and fetch the rig

From the Mac/PC terminal (the Pi must be on the same network):

ssh pi@sonorpi.local
sudo apt update && sudo apt full-upgrade -y && sudo apt install -y git
mkdir -p ~/sonor && git clone https://github.com/sonorltd/sonor-test-rig.git ~/sonor/test-rig
cd ~/sonor/test-rig

If sonorpi.local does not resolve, find the Pi's IP on the router (or on the Pi's desktop: hover the network icon) and use ssh pi@<ip>. The full-upgrade can take 10–15 minutes on a fresh image; a reboot after it is fine but not required.

3 Install the apps

sudo bash install.sh --apps pixel,fractal --front pixel
sudo reboot

This one command, which is safe to re-run at any time:

  • installs the base packages (git, python venv, build tools, Chromium, wlr-randr, unclutter, libportaudio2);
  • links the sonor-rig command into /usr/local/bin and creates /etc/sonor-rig/rig.env;
  • clones Pixel Conductor and Fractal Rig into ~/sonor/<app>/ and runs each project's own installer (Pixel: setup/install-pi.sh; Fractal: setup/install.sh master, which builds the renderer and the master's Python venv);
  • applies the only rig-specific tweaks, as systemd drop-ins: the Fractal web UI moves to port 8081 (the C-Bus daemon needs 8080) and the Fractal renderer runs inside the desktop session instead of as the shipped KMSDRM service;
  • sets up the desktop autostart: a Chromium kiosk on the front app's URL plus that app's display program.

Expect 15–30 minutes: the Fractal installer compiles the renderer and both projects build Python environments. After the reboot the panel boots straight into Pixel Conductor's Perform mode (big touch buttons). Tap Exit on it for the full micro-control UI.

Do not use the projects' install-kiosk.sh scripts on the rig — the rig's own session handles the kiosk. Those scripts are for dedicated field Pis.

If the Fractal Rig clone fails

The sonor-fractal-rig repository may be private. If install.sh reports it cannot clone it, either sign the Pi into GitHub first (sudo apt install gh && gh auth login, then re-run the install command), or copy the project over from the Mac and re-run — the installer uses whatever it finds in place:

scp -r "$HOME/Code/Sonor/STUDIO - Fractal Rig" pi@sonorpi.local:~/sonor/fractal-rig
ssh pi@sonorpi.local sonor-rig install fractal

4 The private repos — C-Bus and eDIN+

sonor-cbus is a private repository, so sonor-rig install cbus needs Git authentication on the Pi (gh auth login, or a deploy key). The simpler route is to copy it across from the Mac and let the installer use the copy:

scp -r "$HOME/Code/Sonor/APP - C-Bus" pi@sonorpi.local:~/sonor/cbus
ssh pi@sonorpi.local sonor-rig install cbus

The C-Bus daemon starts in simulator mode. For a real PCI, edit /etc/sonor-rig/cbus.env and restart:

# 5500PC on an FTDI USB-serial adapter
ARGS=--serial /dev/ttyUSB0 --port 8765 --auth
# or a 5500CN2 on the LAN
ARGS=--tcp 192.168.1.50:10001 --port 8765 --auth
sonor-rig restart cbus

The C-Bus bundled web app only auto-connects when opened by the Pi's LAN IP, not localhost: http://<rig-ip>:8080/.

The eDIN+ ↔ C-Bus bridge is headless (nothing to show on the panel) and also defaults to its built-in simulator. Install it whenever it is wanted:

sonor-rig install edin
sonor-rig logs edin

C-Gate (Java) is not installed by the rig — a real eDIN+/C-Bus network needs it separately; see the bridge's own README.

5 Verify

sonor-rig list      # installed / running / healthy — ▶ marks what is on the panel
sonor-rig doctor    # throttling, temperature, displays, FTDI adapters, session loop
sonor-rig ports     # declared ports · what is actually listening · clashes

What good looks like: list shows every installed app running and healthy; doctor shows throttle flag 0x0, temperature comfortably under 70 °C, two displays and the session loop alive; ports shows no clash. Then from any laptop or phone on the same network:

  • Pixel Conductor full UI: http://sonorpi.local:8760/
  • Fractal Rig full UI: http://sonorpi.local:8081/ (Perform mode: add ?perf=1)
  • C-Bus app: http://<rig-ip>:8080/ (IP, not hostname)

Finally, the switch test:

sonor-rig use fractal   # panel → Fractal perform UI; renderer appears fullscreen on HDMI-A-2 within ~2 s
sonor-rig use pixel     # back again — both daemons kept running the whole time

Driving it — command reference

CommandWhat it does
sonor-rig listWhat is installed / running / healthy; ▶ = the app on the panel.
sonor-rig install <app>Clone + run that project's own installer. Idempotent. all for everything.
sonor-rig use <app>Put that app on the panel (and its display program on the second HDMI). Nothing else stops.
sonor-rig only <app>use it and stop the other apps' services — for when one thing needs all the CPU or the serial bus.
sonor-rig allStart every installed app again.
sonor-rig start | stop | restart | enable | disable | logs <app>Per-app service control; logs follows the journal.
sonor-rig update allgit pull every project and re-run every installer — this is how new versions reach the rig.
sonor-rig portsDeclared ports, what is listening, and any clash.
sonor-rig doctorThrottling, temperature, displays, FTDI adapters, session loop.
sonor-rig add <name>Scaffold apps.d/<name>.app for the next project.

The pi user can run sonor-rig without a password prompt (a sudoers snippet the installer writes — it is a bench, not a site).

Config files

PathPurpose
/etc/sonor-rig/rig.envBench-wide: KIOSK_SIZE=1024,600 · RENDER_DISPLAY=1 (0 = panel, 1 = second HDMI) · RENDER_ARGS= (e.g. --window 1280x720) · CHROME_EXTRA_FLAGS=
/etc/sonor-rig/pixel.envARGS= extra Pixel Conductor args — --simulate when there are no WLED nodes.
/etc/sonor-rig/fractal.envWEB_PORT=8081 · ARGS= extra master args, e.g. --audio or --no-prodj.
/etc/sonor-rig/cbus.envARGS=--simulate --port 8765 by default; real PCI settings above.
/etc/sonor-rig/edin.envARGS=--simulate --log INFO by default; real: --config /etc/sonor-edin-cbus-bridge/config.yaml.
/etc/sonor-rig/currentThe name of the front app. sonor-rig use writes it; the session loop watches it.
~/sonor/<app>/The project checkouts, exactly as a dedicated Pi would have them (pixel-conductor, fractal-rig, cbus, edin-cbus-bridge).
/etc/systemd/system/<unit>.service.d/sonor-rig.confThe per-app drop-ins — the only rig-specific change to how a project runs. The project repos are untouched.

After editing any *.env: sonor-rig restart <app> (or sonor-rig use <app> again for rig.env display changes).

Pixel Conductor and the Fractal master both join the multicast group 239.255.42.1:5005 — the master sends the beat/param stream, the conductor listens. On the rig that delivery is over loopback, so Pixel Conductor's beat clock follows the Fractal master automatically with no configuration.

The one clash: the Fractal master and the C-Bus daemon both default to 8080. The C-Bus port is hard-coded (its app keys off port 8080), the Fractal port is a flag, so on the rig Fractal moves to 8081 via its drop-in. Field Pis keep 8080 — nothing in either project changed.

Two screens

The kiosk lands on the first output; the Fractal renderer goes fullscreen on SDL display RENDER_DISPLAY (default 1 = the second HDMI).

  • Swapped? Either swap the two HDMI leads, or set RENDER_DISPLAY=0 in /etc/sonor-rig/rig.env and run sonor-rig use fractal again.
  • Only the panel attached? Set RENDER_ARGS=--window 1024x600 in rig.env — the renderer opens as a window on the panel for testing.
  • Panel in the wrong mode / black / cropped? Add video=HDMI-A-1:1024x600@60 to the single line in /boot/firmware/cmdline.txt and reboot.

Troubleshooting

SymptomCheck / fix
ssh pi@sonorpi.local can't find the hostUse the IP from the router. On Windows, mDNS may need Bonjour; on the same LAN ping sonorpi.local from a Mac usually works.
install.sh says "run with sudo"It must be sudo bash install.sh …. It is safe to re-run.
Clone of a project fails (auth / 404)Private repo. gh auth login on the Pi, or scp the folder from the Mac into ~/sonor/<dir> and run sonor-rig install <app> (see steps 3 and 4).
Panel shows a desktop, no kiosksonor-rig doctor → session loop. Re-install just the session bits: cd ~/sonor/test-rig && sudo bash install.sh --session-only, then log out/in or reboot.
An app shows unhealthy in listsonor-rig logs <app>. Usually a missing dependency (re-run sonor-rig install <app>) or a port clash (sonor-rig ports).
Fractal renderer never appears on the projectorIs Fractal the front app? (sonor-rig use fractal). Is the projector on HDMI-A-2? Try RENDER_DISPLAY=0, or RENDER_ARGS=--window 1024x600 to prove the renderer runs.
Renderer / kiosk stutters, Pi feels slowsonor-rig doctor: throttle flag ≠ 0x0 means power or heat. 27 W supply + active cooler. Use sonor-rig only <app> while working on one thing.
C-Bus app opens but doesn't connectOpen it by IP (http://<rig-ip>:8080/), not localhost or the hostname.
Pixel Conductor shows no nodesNormal on a bench without Gledoptos — ARGS=--simulate in pixel.env. With real nodes, they must be on the same LAN and answer on port 80.
Fractal UI is on 8081, not 8080Correct on the rig (C-Bus owns 8080). Dedicated Pis use 8080.
Something needs a clean slateRe-image the card and start from step 1 — the whole build is ~1 hour and nothing important lives on the rig except /etc/sonor-rig/*.env (copy those off first if customised).

Adding the next project

cd ~/sonor/test-rig
sonor-rig add hub          # scaffolds apps.d/hub.app from TEMPLATE.app
nano apps.d/hub.app        # REPO, INSTALL (its own installer), UNITS, URL, PORTS
bash tests/test_rig.sh     # lint + port-clash check — no Pi, root or network needed
sonor-rig install hub

Commit the new .app file — that is the whole registration. The tests fail on a listening-port clash, an unexpanded $APP_PATH in systemd text, or a bash default leaking into a unit file.
